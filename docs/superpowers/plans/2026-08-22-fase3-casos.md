# SemioGuia Fase 3 — Casos Clínicos: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Casos clínicos ramificados (árvore com múltiplos desfechos) como grafos declarativos no pipeline de conteúdo, com motor puro, player na aba Estudar e registro de conclusões.

**Architecture:** (1) schema zod do caso + validador estrutural de grafo em `src/content/`; (2) parser e extensão do build (`content/casos/*.md` → `content.json`); (3) motor puro `src/casos/`; (4) store v3 com conclusões de caso (3 adaptadores, migração SQLite); (5) UI: seção na aba Estudar + rota do player; (6) 3 casos piloto de sinais vitais.

**Tech Stack:** o existente (Expo SDK 57, expo-router, TS strict, jest-expo, zod v4, js-yaml no build). Nenhuma dependência nova.

**Spec:** docs/superpowers/specs/2026-08-22-semioguia-fase3-casos-design.md — leia antes; é a autoridade.

## Global Constraints

- Convenções da casa: tokens only via `useTema()`, escala em texto de leitura, pt-BR, a11y (roles/labels, ≥44pt), dois temas, testes co-locados (@testing-library/react-native v14 async render), commits convencionais em inglês, sem identificadores de modelo.
- Validação de grafo (spec §3, verbatim): `inicio` existe; todo `proximo` aponta para nó existente; todo nó alcançável a partir de `inicio`; grafo acíclico; todo caminho termina em `desfecho`; existe ao menos um caminho todo-`otima` terminando em desfecho `otimo`; cada `decisao` tem exatamente uma opção `otima`; `topicosDeApoio` referenciam tópicos existentes; ids de nó únicos no caso; ids de caso únicos no app.
- Conteúdo dos casos: redação original das referências (NUNCA cópia), fatos consistentes com os tópicos aprovados (DBHA 2025, febre adulto >37,8 °C / criança SBP 2025 ≥37,5 °C axilar, FC 60-100), `revisao: pendente`.
- Sem persistência de estado parcial do caso; casos NÃO alimentam o SM-2 (spec §8).
- Ordem de "melhor desfecho": `otimo` > `aceitavel` > `dano`.

### Task 3: Motor do caso

**Files:**

**Interfaces:**
- Consumes: `Caso`, `No`, `Avaliacao` (Task 1).
- Produces (Task 5):

```ts
export interface EstadoCaso { casoId: string; noAtual: string; trilha: { decisaoId: string; opcaoIndex: number; avaliacao: Avaliacao }[] }
export function iniciar(caso: Caso): EstadoCaso;                        // noAtual = caso.inicio, trilha []
export function avancar(caso: Caso, e: EstadoCaso): EstadoCaso;        // só em cena: segue proximo; senão lança

export function nota(e: EstadoCaso): { otimas: number; aceitaveis: number; erros: number };
export function desfechoAtual(caso: Caso, e: EstadoCaso): (No & { tipo: 'desfecho' }) | null; // nó atual se for desfecho
export function noAtual(caso: Caso, e: EstadoCaso): No;                // lança se id não existe (conteúdo validado impede)
```

### Task 5: Telas — lista, player e desfecho

**Files:**
- Modify: `src/app/(tabs)/estudar.tsx` (seção "Casos clínicos" abaixo do quiz por tópico), teste da tela
- Create: `src/app/caso/[id].tsx` (player), Test: `src/telas/caso.test.tsx` (padrão de `src/telas/estacao.test.tsx`)

**Interfaces:** Consumes: Tasks 1-4 (`useCasos`/`useCaso`, motor, `registrarConclusaoCaso`/`listarConclusoesCasos`, tokens/tema). Melhor desfecho: `otimo` > `aceitavel` > `dano`.

Comportamento:
1. **Estudar:** seção "Casos clínicos" (Rotulo + cards): título do caso, contexto em 1 linha, e o melhor desfecho já alcançado ("Melhor resultado: Ótimo" em `ok` / "Aceitável" em `perolaTexto` / "Dano" em `erro`) ou "Não iniciado" em `tinta2`; `useDadosAoFocar` para atualizar; toque → `router.push('/caso/<id>')`. Sem casos no conteúdo → seção não renderiza.
2. **Player:** estado do motor em `useState`. Nó `cena`: texto + card de `dados` (linhas objetivas, fonte mono se houver token, senão corpo) + botão "Continuar" (avancar). Nó `decisao`: pergunta + opções como cards pressáveis (padrão visual do quiz); ao escolher: mostra o `feedback` da opção escolhida (card destacado: `okFundo` se otima, `perolaFundo` se aceitavel, `erroFundo` se erro) + botão "Seguir" que aplica `decidir` e segue. Sem barra de progresso (spec §5).
3. **Desfecho:** classe com destaque visual (otimo→`ok`, aceitavel→`perolaTexto`, dano→`erro`), texto + bloco "O que este caso ensina" com `ensino`; trilha: para cada decisão da trilha, a pergunta, a opção escolhida (com avaliacao) e — quando a escolhida não foi a ótima — a opção ótima indicada ("Melhor conduta: …"); botão "Refazer o caso" (reinicia o motor) e "Voltar". Ao ENTRAR no desfecho: `registrarConclusaoCaso` com `nota(estado)` + `Date.now()` — exatamente uma vez por chegada (guardar com ref/flag; refazer e concluir de novo registra outra conclusão — é histórico).
4. Caso de id inexistente na rota → tela vazia amigável com Voltar (padrão `TelaVazia` existente em `src/app/revisao.tsx` — copiar o padrão local, sem refatorar os existentes).

- [ ] **Step 1: testes que falham** — lista mostra caso e "Não iniciado"; com conclusão prévia (store de memória semeado) mostra "Melhor resultado: Ótimo"; player: cena → Continuar → decisão visível; escolher opção erro mostra feedback e Seguir leva ao desfecho dano com ensino visível; trilha mostra "Melhor conduta"; concluir grava exatamente 1 ConclusaoCaso no store (e refazer+concluir grava a 2ª); id inexistente não quebra.
- [ ] **Step 2:** FALHA; **Step 3:** implementar; **Step 4:** suíte + typecheck + `npm run checar:contraste`.
